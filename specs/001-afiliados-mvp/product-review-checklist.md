# Checklist de revisión de producto

## Utilidad

- [ ] Resuelve un punto de dolor identificado.
- [ ] Es comprensible para el público inicial.
- [ ] Tiene una alternativa o se justifica por qué no.
- [ ] La dificultad de adopción está explicada.

## Evidencia

- [ ] Funciones y casos de uso tienen fuente.
- [ ] Precio y fecha de revisión están registrados.
- [ ] Satisfacción pública tiene fuente, muestra y fecha.
- [ ] No se han inventado cifras, reseñas ni resultados.

## Afiliación

- [ ] Programa activo y solicitud aprobada o pendiente identificada.
- [ ] Política de marca revisada.
- [ ] Restricciones de publicidad y canales revisadas.
- [ ] Cookies, atribución y condiciones de comisión registradas internamente.
- [ ] Enlace de tracking probado sin mostrar datos sensibles.
- [ ] Disclosure visible y enlace con `rel="sponsored"`.

## Calidad de la landing

- [ ] El problema aparece antes que el producto.
- [ ] Incluye limitaciones y para quién no es adecuado.
- [ ] CTA única y clara.
- [ ] No imita la web oficial del proveedor.
- [ ] Responsive, accesible y sin errores de consola.
- [ ] Estado de publicación actualizado.
