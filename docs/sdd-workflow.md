# Flujo SDD

1. Constitución: límites, principios y criterios de calidad.
2. Spec: problema, usuarios, historias, requisitos EARS, casos límite y fuera de alcance.
3. Clarificación: detectar ambigüedades, datos faltantes, riesgos y contradicciones.
4. Plan: arquitectura, modelo de contenido/datos, SEO, analítica, seguridad y decisiones técnicas.
5. Tareas: unidades pequeñas con dependencia, responsable y “hecho cuando”.
6. Implementación: una tarea cada vez; pruebas antes o junto al código cuando sea viable.
7. Validación: recorrido requisito por requisito y revisión visual en navegador.
8. Cambio: modificar primero spec, plan y tareas; después implementar y volver a validar.

## Regla de coordinación

`@director` no delega una petición vaga. Primero convierte la necesidad en un brief con objetivo, usuario, evidencia disponible, restricción y definición de terminado. Cada subagente devuelve: resultado, supuestos, riesgos, archivos afectados y preguntas bloqueantes.
